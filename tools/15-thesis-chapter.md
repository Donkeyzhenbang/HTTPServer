## 第四章 云边协同网关设计与模型闭环迭代机制

### 4.1 多维光学图像感知云边协同系统架构

#### 4.1.1 系统总体架构

电力输电通道巡检是保障电网安全运行的关键环节。传统巡检依赖人工周期性巡视，存在效率低、覆盖不足、弱光场景识别困难等问题。随着边缘计算与深度学习技术的发展，基于视觉 AI 的自动化巡检方案逐渐成为主流。然而现有方案面临三个核心挑战：（1）弱光场景下图像质量差，直接影响缺陷检测准确率；（2）边缘模型一经部署便固化，无法随现场环境变化而进化；（3）大规模设备的接入管理、数据回流与模型升级缺乏系统性方案，采集—训练—部署三个环节相互割裂。

针对上述挑战，本课题设计并实现了"多维光学图像感知云边协同系统软件"。系统采用"云端—网关—边缘"三层协同架构，各层职责分明、通过标准接口解耦，如图 4-1 所示。

> [图 4-1：系统云边端三层架构图]

**边缘层**部署于输电通道现场，由搭载多模态摄像模组（彩色、偏振、红外）与嵌入式计算单元（NPU/GPU）的边缘设备组成。边缘层承担全部在线推理任务：本地运行弱光 HDR 图像增强预处理，随后由 YoloV5 模型完成缺陷检测推理。检测结果与经智能筛选后的关键样本图像通过 TCP 长连接上行至网关。

**网关层**是云边端之间的通信与管控枢纽，基于 C++ 语言实现。核心职责包括：（1）基于 epoll Reactor 模式管理数千个边缘设备的并发 TCP 长连接；（2）私有二进制帧协议的粘包/半包重组与表驱动分发；（3）设备心跳保活与会话管理；（4）巡检图像与推理结果的上行接收与归档；（5）模型权重文件的可靠下行分发。网关层集成 ZooKeeper 客户端和 Redis 客户端，为多网关集群提供分布式协调与会话管理能力。

**云端**不参与任何在线推理计算，仅承担离线训练的职责。云端基于 Ray 分布式计算框架，利用网关归档的现场筛选样本周期性触发模型再训练，训练产出的新模型通过网关下发给边缘设备。

**应用管理层**横跨网关与云端，包含基于 Nginx 的 Web 管理前端，提供设备状态监控、模型版本管理、升级任务下发和历史数据回溯功能。

图 4-2 展示了系统的端到端闭环迭代链路，五个阶段首尾相接，使边缘模型具备随现场数据持续进化的能力。

> [图 4-2：系统闭环迭代五阶段示意图]

```
① 边缘采集 ──► ② 边缘推理 ──► ③ 样本回流 ──► ④ 云端训练 ──► ⑤ 热部署
     ▲                                                              │
     └──────────────────── 循环迭代 ────────────────────────────────┘
```

- **阶段一——边缘采集：** 设备周期性拍摄输电通道多模态图像（彩色 + 偏振 + 红外），支持多曝光模式应对复杂光照
- **阶段二——边缘推理：** 设备本地执行 HDR 弱光增强 + YoloV5 缺陷检测，全部推理计算在边缘端完成

### 4.2 基于 Reactor 模式的高并发设备接入与可靠传输网关设计

网关是连接边缘设备与云端的通信中枢，需要同时管理数百至数千个边缘设备的 TCP 长连接，在私有二进制协议之上可靠地完成巡检图像的上行接收与模型文件的下行分发。本节从事件驱动架构、并发处理模型、协议设计与分包重组、心跳快路径优化和连接生命周期管理五个方面阐述网关的核心设计。

#### 4.2.1 基于 epoll 的事件驱动架构

网关通信层采用 Reactor 设计模式，以单线程 epoll_wait 循环作为核心事件分发器，避免传统"每连接一线程"模型在大规模并发下的上下文切换开销。EventLoop 类封装了 epoll 实例的生命周期管理：

```cpp
class EventLoop {
    void AddSocket(int fd, uint32_t events, EventCallback cb);
    void RemoveSocket(int fd);
    void Run();   // 阻塞式事件循环，最大监听 1000 个 fd
    void Stop();  // 安全退出标志
};
```

**EPOLLET 边缘触发模式：** 系统采用 EPOLLET 边缘触发而非默认的水平触发（EPOLLLT）。ET 模式下内核仅在 fd 就绪状态变化时通知一次，事件回调必须在单次通知内将全部可读数据读尽——通过 while(true) 循环持续 read 直到返回 EAGAIN 或 EWOULDBLOCK。若提前退出，剩余缓冲区数据永不触发新事件，导致协议解析永久阻塞。

**EPOLLRDHUP 半关闭检测：** 系统在 epoll 注册时额外设置 EPOLLRDHUP 标志。当对端调用 close() 或 shutdown(SHUT_WR) 时，内核直接投递该事件，网关无需等待心跳超时即可即时感知设备断连并触发清理流程。

**回调安全执行：** 事件循环执行用户回调前，先从回调表取出 std::function 副本并释放内部锁，再在锁外调用。防止回调内部修改回调表（如注册新 fd 或删除自身）导致的死锁与迭代器失效。

#### 4.2.2 基于线程池的并发处理模型

协议解析与业务处理采用固定大小的线程池，避免每连接动态创建线程的资源开销。线程池基于 std::queue + std::mutex + std::condition_variable 实现，worker 线程数固定为 4。

**CAS 原子防重入：** 为每个连接维护 `std::atomic<bool> is_processing` 标记。IO 线程读取数据后通过 compare_exchange_strong 尝试将标记从 false 原子置为 true——只有 CAS 成功的线程才能将任务入队，保证同一连接的数据包始终串行处理，消除协议状态竞争。

```cpp
bool expected = false;
if (ctx->is_processing.compare_exchange_strong(expected, true)) {
    threadPool.enqueue([fd](){ ProcessConnection(fd); });
}
```

**缓冲区锁与处理锁分离：** IO 线程持锁仅覆盖 read + vector 追加（O(1)），业务线程持锁仅覆盖取一个完整包（O(1)），两锁弱竞争下几乎无阻塞。

#### 4.2.3 私有二进制帧协议与分包重组

为在低带宽、高延时的广域网链路上实现可靠且低开销的数据传输，系统设计了一套定制的二进制帧协议。每帧由同步头（2B）+ 包长（2B）+ CMD ID（17B）+ 帧/包类型（2B）+ 变长载荷 + CRC（2B）+ 尾标识（1B）构成，最小帧长 28 字节，最大 4096 字节。同步头固定为 0x5AA5，CMD ID 为设备 16 字符唯一标识。帧格式详见表 4-2。

> [表 4-2：二进制协议帧格式定义]

**表驱动协议分发：** 预注册静态 HandlerFun 数组，每项为 {frameType, packetType, 处理函数指针} 三元组。ServerFrameResolver 提取帧/包类型字段后遍历匹配并调用对应处理函数。新增协议类型仅需在数组追加一项，分发逻辑零修改，符合开闭原则。

```cpp
static struct HandlerFun Handlers[] = {
    {0x09, 0xE6, HandleHeartbeat},   // 心跳帧
    {0x05, 0xEF, HandleFileStart},   // 传输开始通知 (B351)
    {0x05, 0xF0, HandleFileData},    // 数据块传输   (PhotoData)
    {0x05, 0xF1, HandleFileEnd},     // 传输结束校验 (B37)
};
```

**分包重组机制：** TCP 流式协议不保证消息边界，系统需同时处理粘包、半包和传输乱序：

- **同步头扫描：** FindSyncHeader 逐字节扫描 0xA5 0x5A 序列，丢弃前导无效字节。若无有效同步头，仅保留最后一个字节（可能为 0xA5），其余清空。
- **长度校验：** 读取包长后校验 [4, 4096] 范围，超限则丢弃同步头两字节并重新扫描，防止错位数据导致缓冲区溢出。
- **半包等待：** 若缓冲区数据量不足一个完整包，保留全部数据并退出处理，等待下次 epoll 触发补充。
- **乱序位图：** 文件传输子包携带 subpacketNo，使用 `std::vector<bool> recvStatus` 位图标记接收状态，B37 帧触发完整性统计与缺失报告，支持精确重传。

#### 4.2.4 心跳包 IO 线程快路径优化

千级设备接入场景下心跳包是最频繁的消息（每设备 15-30 秒一次），若每个心跳都完整走"IO 线程入队 → 线程池出队 → 解析 → 回包"路径将产生大量不必要的上下文切换。

**优化方案：** OnClientRead 中检测到以下三条件同时满足时，IO 线程直接内联回包，零入队开销：
1. 单次 read 返回恰好 28 字节（心跳包固定长度）
2. 输入缓冲区为空（排除粘包干扰）
3. 帧头匹配 0x5AA5 且帧类型匹配心跳特征（0x09/0xE6）

该优化将心跳响应延迟从线程调度路径的约 10ms 降至纯 write 系统调用的约 50μs。

#### 4.2.5 连接全生命周期与 Redis 会话管理

网关以有限状态机管理每个 TCP 连接的全生命周期：

```
新建连接 ─► 心跳注册 ─► 数据传输 ─► 断连清理
  │            │            │            │
  │  fcntl +   提取CMD ID  B351-38握手  epoll移除+close
  │  创建上下文  Redis SET   图片/文件   清除上下文
  │  注册epoll   TTL=180s   传输续约    Redis DEL
```

心跳处理函数提取设备 CMD ID 后，向 Redis 写入键 `device:online:<device_id>`，值为 JSON 格式的网关地址信息，TTL 设为 180 秒（3 倍心跳间隔）。设备离线后心跳停止，TTL 自然过期使键自动删除，无需额外定时器轮询。

### 4.3 基于多级级联筛选与私有协议的边缘模型闭环迭代机制

传统电力巡检系统采用"一次性部署"模式——模型在实验室训练完成后固化至边缘设备，此后不再更新。然而在真实输电通道场景中，缺陷类型随季节更替、设备老化、线路改造等因素持续演变，固定模型无法长期维持检测精度。更关键的是，边缘设备全天候运行，每日产生海量的彩色、偏振、红外和 Yolo 检测结果图像——若不加筛选地全部回传云端，将造成严重的带宽浪费、存储膨胀和标注成本飙升。

针对上述问题，本节从两个维度构建边缘模型的闭环迭代能力：（1）**数据维度**——设计六级级联过滤算法在边缘端筛选高价值训练样本，解决"传什么"的问题；（2）**模型维度**——设计四阶段私有协议握手实现模型文件的可靠热更新，解决"怎么传"的问题。两者配合形成"边缘筛选数据 → 云端训练模型 → 网关下发部署"的完整闭环。

#### 4.3.1 "边推理—云训练"闭环总体方案

闭环链路的五个阶段及各阶段执行位置如图 4-3 所示。

> [图 4-3：边推理—云训练闭环迭代全链路]

- **边缘采集（边缘端）：** 设备周期性拍摄输电通道多模态图像（彩色 + 偏振 + 红外，支持多曝光）
- **边缘推理（边缘端）：** 设备本地执行 HDR 弱光增强 + YoloV5 缺陷检测，输出检测结果与置信度
- **样本筛选回流（边缘→网关→云端）：** 经六级级联筛选后的高价值样本通过 B351 协议上行归档至云端数据湖
- **云端训练（云端）：** 现场样本累积至阈值后在 Ray 集群触发分布式再训练
- **热部署（云端→网关→边缘）：** 新模型通过 B351-B38 四阶段握手协议下发至边缘设备

**触发策略与回滚保护：** 数据驱动触发（高价值样本累积 ≥ 500 张）和时间驱动触发（每 7 天全量再训练）互补。新模型部署前验证集 mAP 若下降 ≥ 2%，自动中止并保持线上模型不变。

#### 4.3.2 面向多模态巡检图像的六级级联样本筛选算法

边缘设备全天候运行，日均产生数万张多模态图像。若不加筛选全量回传，不仅浪费带宽与存储，更关键的是大量冗余图像（重复场景、高置信度正常样本、低质量图像）对模型改进的边际贡献趋近于零。本系统设计了**六级级联样本筛选算法**（Six-Stage Cascaded Sample Selection, SCSS），按计算开销从轻到重逐级编排，在边缘端将日均万级图像压缩至百级高价值训练样本。算法流程如图 4-4 所示。

> [图 4-4：六级级联样本回流筛选算法流程图]

```
全天候多模态图像流（彩色 + 偏振 + 红外 + Yolo结果，日均数万张）
        │
        ▼
┌──────────────────────────────────────────────────┐
│ 第一级：图像质量门控                               │
│ Laplacian方差 + 直方图分位数 + 分辨率检查           │  → 滤除模糊/过曝/欠曝
├──────────────────────────────────────────────────┤
│ 第二级：检测置信度筛选                             │
│ Least Confidence + Margin Sampling 双指标评分      │  → 保留模型不确定样本
├──────────────────────────────────────────────────┤
│ 第三级：多模态交叉校验                             │
│ 彩色 ↔ 红外 ↔ 偏振 检测结果一致性判定              │  → 模态不一致 = 高价值难例
├──────────────────────────────────────────────────┤
│ 第四级：时序感知去重                               │
│ pHash感知哈希 + 滑动窗口 Hamming距离               │  → 连续帧去冗余
├──────────────────────────────────────────────────┤
│ 第五级：缺陷类别均衡采样                           │
│ 滑动窗口类频统计 + 反比例采样概率                   │  → 防止长尾退化
├──────────────────────────────────────────────────┤
│ 第六级：特征空间多样性采样                         │
│ Backbone特征嵌入 + K-Means聚类分层采样             │  → 保证场景覆盖
└──────────────────────────────────────────────────┘
        │
        ▼
  高价值训练样本（日均数百张）→ 回传云端
```

**第一级——图像质量门控：** 以极小计算开销快速剔除不可训练的劣质图像。对每张原始图像计算三项无参考指标：Laplacian 方差（模糊度，阈值 < 50 丢弃）、灰度直方图 5%-95% 分位数跨度（曝光异常，跨度 < 30 丢弃）、短边最低分辨率（< 320px 丢弃）。三项中任一不达标即过滤，本阶段滤除约 15%-20% 的技术劣质图像。

**第二级——检测置信度筛选：** 利用边缘端 YoloV5 推理时产出的置信度分数作为筛选信号。引入主动学习中两个经典不确定性指标：

\[
\text{LC}(x) = 1 - P(\hat{y}|x), \quad \text{MS}(x) = P(\hat{y}_1|x) - P(\hat{y}_2|x)
\]

其中 \(\hat{y}\) 为最优预测类别，\(\hat{y}_1, \hat{y}_2\) 为置信度前两高的类别。LC 高表示模型连最优类也不确定，MS 低表示前两类概率接近（决策边界模糊）——两者均为高价值样本信号。所有检出目标置信度均 > 0.9 的样本仅在属于稀有缺陷类别时才予以保留，否则被判定为已充分掌握而丢弃。

**第三级——多模态交叉校验：** 输电通道同一位置同时采集彩色、偏振和红外图像，不同模态对同一缺陷的感知具有互补性——例如绝缘子自爆在彩色图像中表现为纹理突变，在红外图像中对应局部温升，在偏振图像中体现为材料应力变化。本算法利用这种多模态互补特性：计算各模态两两之间的检测结果不一致次数：

\[
S_{\text{cross}} = \sum_{i,j \in \{\text{rgb, ir, pol}\}, i \neq j} \mathbb{1}[\text{det}_i \neq \text{det}_j]
\]

\(S_{\text{cross}} \geq 2\) 表示至少两个模态对同一场景的判断不一致——该样本恰好处于模型的模态决策边界，是最高价值的难例（hard example），优先回流。

**第四级——时序感知去重：** 巡检设备移动过程中，对同一杆塔或导线区段会在数秒内连续拍摄多帧高度相似的图像。若全部回传将导致训练集中出现大量近乎重复的样本，使模型在局部区域过拟合。本算法对通过前三级的候选样本计算感知哈希（pHash）——缩放至 32×32 → DCT 变换 → 取低频 8×8 系数与均值比较 → 生成 64 位哈希码。在滑动窗口（长度 = 30 帧）内计算相邻候选帧的 Hamming 距离：

\[
D_{\text{Hamming}}(h_i, h_j) = \sum_{k=0}^{63} h_i[k] \oplus h_j[k]
\]

若 \(D_{\text{Hamming}} \leq 8\)（约 12.5% 容差），判定为近重复帧，仅保留窗口中置信度最低的那一帧。本阶段通常再削减 40%-60% 的冗余样本。

**第五级——缺陷类别均衡采样：** 电力巡检场景中缺陷类别天然呈长尾分布——"正常"占绝大多数，导线断股、绝缘子自爆等严重缺陷极为罕见。不加控制地回传将使训练集被正常样本淹没。本算法在边缘端维护滑动窗口（最近回传 500 张）的类频统计直方图 \(C = [c_1, c_2, ..., c_K]\)，对候选样本依其检测类别 \(k\) 计算反比例采样概率：

\[
P_{\text{sample}}(k) = \frac{1 / (c_k + \epsilon)}{\sum_{j=1}^{K} 1 / (c_j + \epsilon)}, \quad \epsilon = 1
\]

稀有类以更高概率被采样，常见类被抑制，确保训练集中各类别保持相对均衡。

**第六级——特征空间多样性采样：** 即使经过类均衡，同一缺陷类内部仍可能存在大量视觉相似的样本（同一角度、同一光照下的同一设备）。为保证回流样本在特征空间中的覆盖度，利用 YoloV5 Backbone 中间层特征图（C3 层输出，经 GAP 池化为 512 维向量）作为图像嵌入。对候选集特征向量运行 K-Means 聚类（K = 候选集大小的 1/5，最少 5 簇），从各簇按簇大小反比例抽取等量样本，确保回流的训练样本覆盖不同的拍摄角度、光照条件和背景场景，最大化单次训练迭代的信息增益。

**边缘端计算部署：** 前三级（质量门控、置信度筛选、多模态校验）融合于推理后处理流程中实时执行，计算开销可忽略不计。后三级（时序去重、类别均衡、多样性采样）在设备空闲时段（夜间无巡检任务时）批量执行。最终选定的回流样本附带每级的筛选评分元数据（JSON 格式），便于云端训练时按样本质量加权。

#### 4.3.3 基于私有协议握手的模型热更新机制

筛选后的高价值样本触发云端再训练，训练产出的新模型需要可靠地从云端下发至分散的边缘设备。模型权重文件通常为数十 MB 的二进制文件（.pt / .onnx），在广域网链路上传输面临三个挑战：大文件可靠分块、传输中断恢复、接收端安全替换。系统设计了四阶段握手协议——B351（传输通知）→ B352（设备确认）→ PhotoData × N（数据块传输）→ B37（结束校验）→ B38（最终确认）。

```
网关（发送端）                              边缘设备（接收端）
 │                                              │
 ├── B351(channelNo, totalPackets) ────────────► ① 通知通道号与总包数
 │                                              │
 │◄── B352(Ack) ───────────────────────────────┤ ② 设备确认就绪
 │                                              │
 ├── PhotoData(subpacketNo=0, 1024B) ──────────► 
 ├── PhotoData(subpacketNo=1, 1024B) ──────────► ③ 分块传输
 ├── ... 共 N 包 ...                             │
 ├── PhotoData(subpacketNo=N-1, ≤1024B) ───────► 
 │                                              │
 ├── B37(totalSize, checksum) ─────────────────► ④ 传输总量 + 校验信息
 │                                              │
 │◄── B38(Final Ack) ──────────────────────────┤ ⑤ 设备确认接收完成
```

**mmap 内存映射零拷贝：** 网关发送模型文件前，通过 `open() → fstat() → mmap()` 将文件映射到进程虚拟地址空间。发送 PhotoData 包时指针直接引用映射区中对应偏移——内核通过缺页中断按需加载磁盘数据至页缓存，避免了 `read()` 系统调用从页缓存到用户缓冲区的额外拷贝。

**1024 字节固定分包与断点续传：** 每包载荷固定 1024 字节（末包可能不足），总包数 = ⌈fileSize / 1024⌉。固定小包设计使大文件发送不独占连接窗口，心跳和控制消息可交错发送。设备端使用 `std::vector<bool> recvStatus` 位图索引接收状态——若传输因网络中断中止，设备重连后可请求从第一个缺失偏移处续传，无需从头重传。

**POSIX rename 原子替换：** 设备端收全数据后，将 B37 携带的校验信息与本地计算结果比对。校验通过后将完整数据写入临时文件，再通过 POSIX `rename()` 系统调用原子替换活跃模型文件——rename 在 POSIX 语义下为原子操作，不会出现"文件写一半即被加载"的不一致状态。

#### 4.3.4 样本标注与云端分布式训练

**数据标注管线：** 经六级筛选回流传的样本附带筛选评分元数据。网关按设备 ID、时间戳和评分组织存储。前端标注工具依据评分从高到低排列待标注图像，帮助运维人员优先标注信息量最丰富的样本。

**云端训练架构：** 标注完成的数据集推送至云端训练服务器。训练环境基于 Ray 分布式计算框架构建——Ray Head Node 负责任务调度与数据集分发，多个 Worker Node 并行执行 YoloV5 训练任务。训练完成并通过验证集 mAP 评估后，新模型推送至网关的模型仓库等待下发。

**自动化演进方向：** 后续将引入主动学习策略自动筛选最具标注价值的样本以减少人工标注量，同时引入 Redis Stream 消息队列实现"样本归档 → 训练触发 → 训练完成 → 模型升级"的全自动化链路。

#### 4.3.5 多网关分布式协同管理

当系统扩展至多网关集群时，需解决服务发现、设备归属和互斥访问三类分布式协调问题。本系统基于 Apache ZooKeeper 实现统一的协同管理层，其命名空间设计如图 4-5 所示。

> [图 4-5：ZooKeeper 命名空间结构]

```
/gw-server/
├── nodes/              # 网关实例注册 (Ephemeral)
│   ├── node_192.168.1.10_52487
│   └── node_192.168.1.11_52487
├── election/master/    # 主节点选举 (Ephemeral Sequential)
│   ├── candidate_0000000001 ← Master
│   └── candidate_0000000002
├── config/             # 分布式配置
│   ├── model_version   # 线上模型版本号
│   └── sample_threshold  # 样本筛选阈值
└── locks/              # 设备级分布式锁
    └── device_<id>
```

- **服务发现：** 网关启动时在 /nodes/ 下创建 Ephemeral 节点，携带 IP、端口和状态。进程退出或断网时 ZK 自动清除节点。
- **主节点选举：** 各实例在 /election/master/ 下创建 Ephemeral Sequential 节点，按字典序最小者当选 Master，负责全局任务调度。通过 Watcher 监听，Master 下线自动重选。
- **分布式设备锁：** 模型升级等关键操作要求同一时刻仅一台网关与目标设备交互。基于 ZK Sequential Ephemeral 节点 + 前驱监听实现公平锁。

### 4.4 系统测试与评估

#### 4.4.1 网关性能测试

网关性能是系统稳定运行的基础。测试环境为 4 核 8GB 云服务器（运行网关进程）与模拟设备客户端（基于 Python 多线程模拟 N 个并发 TCP 连接）。测试项与结果汇总于表 4-3。

| 测试项 | 测试方法 | 测试条件 | 目标指标 | 实测结果 |
|--------|---------|---------|---------|---------|
| 并发连接数 | 递增客户端直至网关 accept 失败 | 单网关进程 | ≥ 1000 | 待测 |

### 4.5 本章小结

本章围绕多维光学图像感知云边协同系统的核心软件设计与实现，重点阐述了三项工作：

（1）**系统整体架构设计：** 给出了"云端—网关—边缘"三层协同架构，明确了云端仅做离线训练、边缘端承担全部在线推理的职责划分，并通过技术选型表说明了各层的组件选择依据。

（2）**基于 Reactor 模式的高并发设备接入网关：** 采用 Linux epoll ET 模式与固定线程池实现数千 TCP 长连接的高效管理；设计了私有二进制帧协议及表驱动分发机制，通过四层策略协同解决了流式传输的粘包/半包/乱序问题；针对高频心跳设计了 IO 线程快路径优化，将响应延迟从毫秒级压缩至微秒级；结合 Redis TTL 实现了无需额外定时器的会话管理。

（3）**基于多级级联筛选与私有协议的边缘模型闭环迭代机制：** 设计了六级级联筛选算法（SCSS），从图像质量、检测置信度、多模态交叉校验、时序去重、类别均衡和特征多样性六个维度在边缘端筛选高价值训练样本；设计了 B351-B38 四阶段握手协议实现模型文件的可靠热更新，采用 mmap 零拷贝、固定分包位图校验和 POSIX rename 原子替换保证传输可靠性与安全性。基于 ZooKeeper 的分布式协调层支撑了多网关集群的自组织管理。

当前系统已完成网关核心通信层和模型升级协议的主要开发工作，后续将继续推进数据回流自动化、主动学习样本筛选和全链路监控告警体系的建设。
